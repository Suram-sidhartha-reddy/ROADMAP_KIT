ML Engineer
Field Manual

What they don't put in blog posts. Includes production realities, hiring filters, debugging instincts, and the non-obvious things that separate L4 practitioners from L6 ones.

Duration: 8–12 months
Phases: 8
Covers: Core ML → MLOps → Research Engineering
// How to Use This

This roadmap is structured into two parts: Part 1 — ML Engineering Core (Months 1–5) builds the practitioner foundation, and Part 2 — Production ML & Specializations (Months 5–10) builds the systems and niche depth that actually gets you hired.

Items marked INSIDER are things most courses skip but working professionals consider table stakes. These are the things that get flagged in code reviews, blow up at 3am in production, and come up in staff-level system design rounds.

PART 01 / ML Engineering Core
PHASE 01

Mathematical Foundations That Actually Matter

Weeks 1–4 · Don't skip this
Linear Algebra
  • Vectors, matrices, matrix multiplication — not just operations but geometric intuition
  • Eigendecomposition and SVD — understand what singular values represent (energy, signal strength)
  • PCA from scratch — why you'd use it and when it lies to you Insider
  • Matrix rank and null space — how they relate to underdetermined systems in regression
  • Numerically stable implementations — why naive dot products lose precision at scale Insider
Probability & Statistics
  • MLE vs MAP — and when MAP silently becomes L2 regularization Insider
  • Bayes' theorem applied to model calibration, not just toy examples
  • Calibration vs accuracy — a model can be 95% accurate and completely uncalibrated Insider
  • KL Divergence — the actual math behind VAEs, knowledge distillation, and RLHF reward modeling
  • Central Limit Theorem applied to A/B testing validity — most ML A/B tests are run wrong Insider
  • Expected value framing for business metrics — how to translate model outputs to dollar values
Calculus for ML
  • Chain rule — not the textbook version, the computational graph version
  • Jacobians and Hessians — when they matter (second-order optimizers, curvature estimation)
  • Numerical gradient checking — how to verify your backprop is correct Insider
⚠ Professional Reality

Most ML bugs in production aren't model architecture bugs — they're numerical stability bugs, shape broadcasting errors, or gradient explosion/vanishing that manifests slowly over training. The math here is what lets you read the symptom and find the cause.

PHASE 02

Classical ML — Deeper Than You Think

Weeks 4–8
Core Algorithms (Implement, Don't Just Call)
  • Linear/Logistic Regression — implement with gradient descent and normal equations; understand when each fails
  • Decision Trees — implement ID3/CART from scratch; understand split criteria geometrically
  • Random Forests — understand out-of-bag error; why it's a free validation set Insider
  • Gradient Boosting — understand the additive model view, not just "XGBoost is fast"
  • SVM — understand the kernel trick geometrically; when to use over neural nets
  • K-Means — convergence guarantees (or lack thereof); K-Means++ initialization matters Insider
What Industry Adds That Courses Skip
  • Feature importance ≠ causation — SHAP values and their limitations in correlated features Insider
  • Class imbalance: SMOTE is often worse than you think; try class weights first Insider
  • Data leakage patterns — future data in features, target-encoded in wrong order, ID columns correlated with label Insider
  • Cross-validation strategies: time-series CV, group K-fold, stratified — wrong choice = misleading metrics Insider
  • Calibration curves: Platt scaling and Isotonic regression for probability calibration
  • When to not use ML — a decision tree on rules sometimes beats a neural net and is debuggable Insider
Must-Build Projects
Tabular churn prediction (full pipeline) Fraud detection with severe imbalance Time-series forecasting (retail) Feature store prototype
PHASE 03

Deep Learning Engineering

Weeks 8–14
Training Mechanics (The Real Ones)
  • Backpropagation through computational graphs — implement autograd in NumPy Insider
  • Optimizer internals — SGD, Momentum, AdaGrad, Adam — understand why Adam's bias correction matters at step 1 Insider
  • Learning rate schedules — warmup + cosine decay is default at every serious lab Insider
  • Batch size scaling laws — why doubling batch size often needs LR doubling (linear scaling rule)
  • Gradient clipping — by value vs by norm; why norm-clipping is almost always preferred Insider
  • Mixed precision (FP16/BF16) — numerical edge cases; BF16 over FP16 for LLMs specifically Insider
  • Gradient accumulation — how to simulate large batches on small GPUs
Architecture Patterns
  • CNNs — receptive field calculations; depthwise separable convolutions (efficiency trick)
  • Residual connections — why they work (gradient highway), not just that they work
  • Attention mechanism — implement multi-head attention from scratch before using nn.MultiheadAttention
  • Transformers internals — positional encoding variants (sinusoidal, RoPE, ALiBi); why they differ at long context Insider
  • LayerNorm vs BatchNorm — when each fails (BN fails on small batches; LN fails on early training sometimes)
  • Weight initialization — Kaiming vs Xavier; wrong init = dead network from step 1 Insider
Debugging Neural Networks (Nobody Teaches This)
  • Loss not decreasing? Overfit one batch first — if it can't memorize 1 sample, architecture is broken Insider
  • Check gradient norms per layer — exploding/vanishing is layer-specific, not global
  • Visualize activations and weights — dead neurons (all-zero activations) are invisible without this
  • Label smoothing's hidden effect — improves calibration but hurts accuracy on noisy labels Insider
  • Loss landscape flatness — sharp minima generalize worse; SAM optimizer exists for this reason
  • NaN hunting — enable gradient anomaly detection in PyTorch during debug only Insider
🔥 Professional Reality
  • Training runs that look fine for 5k steps can diverge at 20k. Always log gradient norms.
  • Evaluation loss ≠ task metric. You need both. Most teams learn this after their first production incident.
  • Reproducibility requires: fixed seeds, deterministic CUDA ops, and pinned library versions — in that order.
PHASE 04

NLP & LLM Engineering

Weeks 12–18 · High-value niche
Tokenization & Embeddings
  • BPE, WordPiece, SentencePiece — how vocabulary size affects out-of-vocabulary behavior Insider
  • Tokenizer-model mismatch — fine-tuning with a different tokenizer than pretraining = silent degradation Insider
  • Embedding space geometry — anisotropy problem in sentence transformers and how whitening fixes it
  • Context window vs effective context — attention sinks, lost-in-the-middle effect Insider
Fine-Tuning & PEFT
  • Full fine-tuning — when it's still the right call (small datasets, task is very far from pretraining)
  • LoRA internals — rank selection heuristics; low rank ≠ always good Insider
  • QLoRA — 4-bit quantization + LoRA; VRAM math to fit models on consumer GPUs
  • Catastrophic forgetting — why instruction-tuned models forget general abilities; replay buffers Insider
  • DPO vs PPO for RLHF — DPO is simpler but brittler on distribution shift Insider
  • Prompt sensitivity — same model, different prompt order = 10–20% accuracy swing on benchmarks Insider
RAG Systems (Real Implementation)
  • Chunking strategies — recursive character splitting vs semantic chunking; chunk overlap tradeoffs
  • Embedding model choice — domain-specific embeddings often beat general ones; MTEB leaderboard is your starting point
  • Retrieval failure modes — query-document mismatch, late chunking, top-k not enough Insider
  • Hybrid search — BM25 + dense retrieval + RRF reranking; dense alone loses on keyword queries Insider
  • Reranker models (cross-encoders) — when to add; latency vs quality tradeoff
  • Hallucination isn't random — it correlates with retrieval confidence; log retrieval scores Insider
  • RAG evaluation metrics — RAGAS, faithfulness vs answer relevancy vs context recall
LLM Inference Engineering
  • KV cache — what it stores, why it grows with context length, how PagedAttention solves it
  • Quantization — GPTQ, AWQ, GGUF formats; perplexity vs downstream task accuracy gap Insider
  • Speculative decoding — draft model + verifier; 2–3x speedup with no accuracy loss
  • Batching strategies — static vs dynamic vs continuous batching; throughput vs latency tradeoff Insider
  • vLLM vs TGI vs Ollama — know when each is appropriate at scale Insider
PART 02 / Production ML & Systems
PHASE 05

MLOps & Production Systems

Weeks 16–22 · The career differentiator
The ML Lifecycle Nobody Draws Accurately
  • Data versioning — DVC, LakeFS; why Git for code and Git for data are different problems Insider
  • Training pipelines — reproducibility means same data, same code, same config — not just "same seed" Insider
  • Experiment tracking — MLflow / W&B; logging hyperparams, system metrics, artifacts together Insider
  • Model registry — staging → production → archived; rollback isn't just redeploying old code Insider
  • Feature stores — Feast, Tecton; training-serving skew is the #1 silent production killer Insider
Serving & Deployment
  • REST vs gRPC for model serving — gRPC for low latency inter-service; REST for external APIs
  • ONNX export — export from PyTorch, run anywhere; shape inference pitfalls Insider
  • Model warming — cold start latency is real; first request spike causes SLA breach in prod Insider
  • Canary deployments for models — shadow mode → 5% → 25% → 100%; traffic splitting logic
  • Triton Inference Server — batching, multiple backends, GPU concurrency controls Insider
  • Async inference — queue-based for heavy models; polling vs webhooks for results
Monitoring (The Part That's Always Broken)
  • Data drift vs concept drift — P(X) shifts vs P(Y|X) shifts; different detection methods for each Insider
  • PSI (Population Stability Index) — industry-standard drift metric; know the 0.1 / 0.2 thresholds Insider
  • Upstream data contract testing — your model fails silently when a schema changes upstream Insider
  • Label delay problem — ground truth arrives days/weeks after prediction; how to design evaluation around it Insider
  • Alerting on model metrics, not just infra metrics — latency being fine doesn't mean the model is fine Insider
✓ The Interview Filter Most Candidates Fail

Staff ML engineers at FAANG/Series B+ startups will ask: "Your model went to prod last Tuesday. How do you know if it's working right now?" — If your answer is only "I check accuracy on the test set," you're not ready. The answer involves feature distribution monitoring, prediction distribution tracking, business metric correlation, and upstream data health checks running simultaneously.

PHASE 06

Distributed Training & Compute Efficiency

Weeks 20–26 · Required for large-model roles
Parallelism Strategies
  • Data parallelism — DDP vs FSDP; FSDP shards optimizer state (critical for 7B+ models) Insider
  • Tensor parallelism — Megatron-style; split individual weight matrices across GPUs
  • Pipeline parallelism — GPipe/1F1B schedule; bubble overhead and how microbatches reduce it Insider
  • 3D parallelism — combining all three; used for 70B+ training runs
  • ZeRO optimizer stages (0/1/2/3) — stage 3 shards everything but has communication overhead Insider
GPU Performance Engineering
  • Memory bandwidth vs compute bound — profiling determines which you are; different optimizations for each Insider
  • CUDA kernel basics — memory coalescing, warp divergence; you don't need to write CUDA but must read profiles
  • FlashAttention — IO-aware attention; why it's 3–5x faster without approximation Insider
  • torch.compile and TorchInductor — graph capture gotchas with dynamic shapes Insider
  • Gradient checkpointing — recompute activations to save memory at cost of 30% more compute Insider
  • Profiling tools — PyTorch Profiler, NVIDIA Nsight; trace files tell you where time actually goes Insider
PHASE 07

ML System Design

Weeks 22–28 · The interview round that filters seniors
ML System Design Framework
  • 1. Clarify the ML task — classification/regression/ranking/generation; online vs batch inference
  • 2. Define the objective — business metric → proxy metric → model metric; misalignment here = wrong model Insider
  • 3. Data strategy — sources, labeling cost, weak supervision, data flywheel
  • 4. Feature engineering — real-time vs precomputed; feature store architecture
  • 5. Model selection — start simple; complexity budget vs latency budget
  • 6. Offline evaluation — metrics, bias analysis, failure mode analysis
  • 7. Online evaluation — A/B test design, guardrail metrics
  • 8. Deployment + monitoring — serving infra, drift alerts, rollback plan
Common ML System Design Problems
Recommendation System (Netflix / Spotify)
  • Two-tower architecture — candidate generation vs ranking stage; why separate stages
  • Exploration vs exploitation — epsilon-greedy, UCB, contextual bandits; pure ML = filter bubble Insider
  • Cold start: new user, new item — content-based fallback strategy
  • Implicit feedback (clicks, watch time) vs explicit (ratings) — implicit is noisier but far more abundant
Ad Click-Through Rate Prediction
  • Calibration is more important than AUC here — advertisers bid on calibrated probabilities Insider
  • Feature interactions — DeepFM, DCN; cross features for sparse categoricals
  • Real-time feature computation — last N clicks, session context; sub-10ms latency requirement
  • Position bias in training data — clicks are affected by position; debias with inverse propensity scoring Insider
Search Ranking (Google / LinkedIn)
  • Learning to Rank — pointwise, pairwise (RankNet), listwise (LambdaMART) — listwise wins but needs more data
  • Query understanding — spell correction, entity recognition, query expansion
  • NDCG as metric — position-weighted; first result matters 4x more than third
  • Freshness vs relevance tradeoff — time decay factors in ranking scores Insider
Fraud Detection / Anomaly Detection
  • Real-time scoring — must score in <100ms; feature computation is the bottleneck, not the model
  • Feedback loop problem — blocking fraud means no ground truth on blocked transactions Insider
  • Graph features — device/IP/account rings; GNNs for connected fraud rings
  • Rule engine + ML hybrid — rules for known patterns, ML for new ones; never replace rules entirely Insider
PHASE 08

The Non-Technical Skills That Gate Hiring

Ongoing — Start Month 1, Never Stop
Experiment Mindset
  • Hypothesis-driven iteration — every experiment should have a falsifiable hypothesis before running it Insider
  • Keep experiment logs — what you changed, why, what happened; reviewers will ask for your reasoning chain
  • Negative results are results — document why things didn't work; it saves the next engineer 2 weeks Insider
  • Compute budgeting — justifying GPU hours is a real conversation at senior levels
Communication (Underrated, Career-Defining)
  • Write model cards — document limitations, training data, evaluation gaps; this is now an industry expectation Insider
  • Metric storytelling — +1.2% AUC means nothing to a PM; convert to revenue impact or user experience delta
  • Disagreement with stakeholders — learn to say "this will hurt the model" without killing the relationship
  • Design docs — write a 1-pager before building any significant feature; senior engineers live by this Insider
Research Literacy
  • Reading papers — abstract → intro → experiments → conclusion; skip related work first read
  • Reproduction gap — 60–70% of paper results don't reproduce in different settings; be skeptical Insider
  • arxiv Sanity / Papers With Code — find state-of-art baselines for any task before starting
  • Ablation studies — always run them before claiming your contribution matters Insider
